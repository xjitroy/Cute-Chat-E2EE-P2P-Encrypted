# Security notes for this candidate

Preserve original transactional Signal state and encrypted vault; do not restore ratchets from stale backups or reset user storage to bypass signing. Standard cryptographic libraries are used. Android/native call/media/network/installer policy remains authoritative; no root, silent installer, hidden mandatory foreground notification or universal wake promise.

The in-app updater enforces exact public repository/tagged asset URL and size, strict bounded metadata, HTTPS host/redirect validation, explicit download, byte/hash integrity, matching package/capability/minSDK/non-debuggable APK and exact current signer-set preflight. Android finally verifies APK signatures and asks the user to install. Corrupt, truncated, extra-byte, wrong signer or same/older-version files cannot be accepted as a verified update. A compatible key-rotation scheme is not implemented; changing signers needs separate review.

208 JVM tests per flavor pass, lint has0errors (warnings recorded in VALIDATION.json),22 Android cases per flavor compile but0execute. Android permission return/denial, cancel, real successful in-place update, retained encrypted history, calls and source-provider boundaries still require phone tests. Preview geometry/swipe policies pass eight new host cases, but host mathematics is not live camera/gesture performance proof. Actual preview/QR/permission/large-type/reply/call/sidebar behavior still requires physical testing. No external penetration audit or production certificate claim. Report vulnerabilities privately to the repository owner; do not post keys, chat contents or exploit details in public issues. GitHub private vulnerability reporting is not currently enabled; privately contact the repository owner rather than disclosing sensitive exploit details in public issues.
