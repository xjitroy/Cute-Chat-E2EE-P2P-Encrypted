# Cute Chat0.4.14 — QR orientation and native navigation polish

Clean public product snapshot, derived from the reviewed native source. Version code35, runtime0.4.14. Existing package/signing certificate/identity/Signal/vault and update security checks are preserved. The owner authorized public Normal/source publication on 2026-10-14. No Worker deployment or private key/user-photo upload.

Reviewed owner screenshots30018/30027/30033/30030: the scanner preview was sideways, five bottom items crowded/truncated labels, QR/scan controls occupied much of the page, two contact-helper buttons were present on that page, and the entry/security copy was terse and inconsistent. Actual owner screenshots/QR/profile/photo contents are NOT copied to the repository or candidate ZIPs.

Only the Scan & my ID page loses Add by private ID / phone Contacts and Save my ID in phone Contacts. The Home plus/private contact hub and contact export helpers remain. Own-ID saving is accessible in Settings → Account. The bottom navigation now has only Chats, Calls, Media and Sharing with fixed equal widths/short labels. Scan/ID remains an auxiliary page accessible from Home's QR button, the contact hub, chat QR/header gesture and the existing horizontal virtual-page route. It is represented by Chats in the four-item bar; tapping Chats returns Home. No removal of QR/invitations/profile/native-auth/contact features.

Scanner and signed own QR share the same first-page horizontal panel. The ID label stays masked until tapped and resets on pause. The own QR always remains visible, has a four-module white quiet margin, and can be tapped to show a larger secure dialog; dialog-owned bitmap/callback cleanup prevents navigation from recycling an image still being drawn. The profile photo shortcut, contact Share and manual Paste remain. Opening QR while initial identity storage is still loading now refreshes once ready; the old root-null condition could leave the page stuck on its preparing placeholder. The Camera button now restarts ONLY the inline permission-guarded camera; it no longer launches a separate system scanner when permission is already granted. Optional system scanner lives in Scanner options and remains an explicit fallback. Smaller screens/large type scroll naturally; enlarge the QR when its compact preview is too small for another camera. QR is a public signed contact invitation, not an encryption secret; masking the separate ID text does not conceal QR identity material.

Camera2 SurfaceTexture already supplies sensor-orientation transformation. The previous preview matrix added the sensor angle again, rotating the portrait image. New geometry compensates actual display rotation and preserves the sensor-oriented image's aspect with centered crop. Reapply on SurfaceTexture resize and DisplayManager rotation changes, including180degrees. Preview/YUV configurations now require a common supported bounded size, at most1280x720. The YUV QR decode path is unchanged and bounded; no photograph/microphone/file/upload, and generation/foreground/page/call/auth/permission gates remain. Actual OEM0/90/180/270 preview orientation/decode still requires physical validation; geometry unit tests are not camera proof.

Horizontal browsing uses native VelocityTracker, direction/slop filtering, light bounded drag feedback and220ms Material-style settling/entry. A short drag cancels/returns; a deliberate same-direction flick can complete. Interrupted/background gestures reset, stale page/locked/call-screen gestures do not navigate, and no delayed navigation callback, screen snapshot, duplicated live camera or secondary capture session is created. RTL direction is supported. Native text fields, seek bars, horizontal scrollers, switches and bottom-nav touches are excluded; chat-row replies and full-screen call tap/hide remain separate. Primary pages can still be browsed while a background call is active; the call screen itself is not a tab swipe target. Native animation/reduced-motion settings remain honored. Page rebuilding/navigation does not change peer encryption/file transfer ownership.

Entry and pull-down security panel now use consistent localized E2EE · Direct P2P plus explicit end-to-end encrypted messages/calls/files directly between devices. Private history is encrypted locally. Home disclosure still distinguishes connection/notification coordination metadata and readable exported Quick Share Downloads copies. The unlock landing uses the chosen English/Bengali/Hindi/Russian copy instead of a hardcoded English badge. Native Android biometric/password UI is still controlled by Android; do not promise to redesign its system prompt, bypass authentication, military certification or100percent security.

Eight new JVM cases check portrait no-double-rotation, all sensor/display combinations with aspect/crop, resize/half-turn/invalid geometry, deliberate/cancelled/flick/RTL/virtual-QR navigation and rejection of invalid/call/lock targets. Existing Android navigation regression expects four items instead of a stale three-item count; its every-entry authentication case explicitly tests strict0-minute mode, not the default5-minute grace. A new synthetic-only Android QR layout regression verifies paired scanner/code, four nav items, scoped button removal and retained FLAG_SECURE without granting CAMERA or bypassing native credentials.
