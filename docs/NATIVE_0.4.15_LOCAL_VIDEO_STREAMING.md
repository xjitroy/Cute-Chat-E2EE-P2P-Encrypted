# Cute Chat0.4.15 — local video and streaming repair

Owner reports Wi-Fi/hotspot calls reaching the other phone without visible video, and1–2MB/s sharing even on5GHz. Version0.4.15/code36 preserves original package/signer/identity/vault/Signal/secretstream protocol records, Normal/Assist split and in-app updater. Public Normal/source update is explicitly requested; debug/development history stays private. Existing production Worker is not changed.

## Local calls

The installed WebRTC SDK's default network-change request requires NET_CAPABILITY_INTERNET. A WifiNetworkSpecifier/local-only hotspot can therefore be missed after the data factory starts. NativeRtcNetworks installs an idempotent supported NetworkChangeDetectorFactory before the first owner factory, keeps the default SDK detector and additionally reports non-Internet Wi-Fi's real networkHandle/interface/IP list through SDK public APIs. It merges active lists, handles available/capability/link changes/loss, bounds callback registration to detector lifetime, and unregisters on destroy. No process-wide network binding, radio switching, media relay, credentials or new permission. Hotspot-host unmanaged interfaces still use the existing host-interface enumeration path.

Unified Plan video is now observed through onTrack as well as onAddTrack; missing remote tracks are refreshed from SDK receivers after SDP and during the active call. Removal clears the matching remote track. Continued ICE gathering handles interface changes. LAN codec ordering prefers interoperable baseline H264/VP8 before fitted modern codecs, while preserving all modern/RTX/FEC alternatives and SDK SDP/DTLS-SRTP generation. Internet's existing fitted H265/VP9 preference remains. No raw SDP rewrite or lossy-video-as-lossless claim. These fixes address identifiable code gaps; real two-phone video/audio/rendering validation still remains required.

## Live file throughput and integrity

The previous sender admitted only128KiB beyond recipient progress and polled every5ms; each local length/payload wrote/flushed separately and each record scheduled owner work. The live window is now bounded4MiB on Wi-Fi,1MiB on Internet,512KiB during calls; local encrypted queue2MiB plus64KiB control headroom.32KiB secretstream/wire records remain compatible. Both accepted and outbound sockets get TCP_NODELAY/keepalive and request1MiB TCP buffers; Android may clamp them.128KiB buffered reads/writes and bounded flush batches combine syscalls, but control/audio and drain flush immediately. Writer callbacks coalesce every16ms or queue drain; urgent queues stay prioritized.

Recipient checkpoints are coalesced on a50ms scheduled owner task, with64KiB trigger and tail checkpoint/retry. Scheduling rather than waiting for a later chunk preserves old128KiB senders and prevents tail deadlocks. Sender uses notified, bounded waits and verified monotonic ACKs; cancellation/resume wake waiters, progress stalls fail, pauses retain the10minute bound. The old35ms per32KiB live sleep is removed; a smaller concurrent-call window reserves headroom. Private spooled transfers keep encryption and improve buffering;2ms concurrent-call pacing replaces35ms. Rates use250ms verified-byte sampling, hide stale/duplicate rates and retain Long counts. No whole-file RAM allocation, no compression/recompression or altered authentication/final original SHA256/length checks. Accepted files remain pending until authenticated FINAL/integrity completion; corrupt or interrupted partials are discarded.

4GB in2–4minutes requires roughly17–34MB/s actual sustained end-to-end throughput. Radio/storage/CPU/thermal/distance/interference determine real speed;5GHz alone does not guarantee that result. Host loopback tests are transport/integrity evidence, not phone Wi-Fi throughput evidence.

## Clear role/permission flow

Local Send explicitly says Wi-Fi, Receive says Hotspot. Receiver hosts and selected sender joins when a new link is needed; already authenticated same-Wi-Fi/hotspot is reused. Bluetooth remains discovery/consent/setup, not the bulk-file pipe. Sharing displays automatic setup and manual fallback instructions: enable the receiver's hotspot and join it on the sender through Android Wi-Fi settings, then return to the same tab. Android permissions/connection approval and verified sender/file acceptance remain mandatory. Sender selects files first and matches Cute Chat name/ID suffix; no raw Bluetooth system-name list, silent radio toggle, guaranteed wake or auth bypass.

Negotiated wifi_band capability adds an optional strict Boolean5GHz support claim inside the existing authenticated Bluetooth request. Old peers get the unchanged request. On API36+, if both radios advertise5GHz support, only the public SoftApConfiguration.Builder.setChannels/startLocalOnlyHotspotWithConfiguration API is used; Android generates secured SSID/credentials. Rejection/unsupported country/hardware falls back once to the compatible system hotspot. Older Android leaves band choice to the system; existing user-connected5GHz stays in use. Gate/peer/session/expiry checks and no active-call radio switch remain. A four-stage native animation reflects real selection/connection/transfer/save state; percentage/rate/ETA widgets update in place rather than rebuilding all cards/buttons each second. Reduced motion and large-text ellipsis/accessibility preserved.
