# Cute Chat 0.4.17 — Send/Receive radio preparation

Send selection automatically prepares required radios, then Bluetooth signed/Signal-encrypted peer controls deliver the receiver's temporary hotspot SSID/password and the sender joins through the public Wi-Fi network-specifier API. Receiver only hosts after accepting a verified sender; no manual password entry in the supported handoff path. Existing same-Wi-Fi links are reused. Bluetooth pairing/discoverability and Wi-Fi joining may require Android consent; no bypass, hidden APIs, device administration or global network binding.

Fixes: Android12+ Receive now declares/requests BLUETOOTH_ADVERTISE only when needed for discoverability, in addition to existing Connect/Scan, and catches OS discoverability refusal. Sender Wi-Fi-off now opens the native Android10+ Wi-Fi panel and resumes only if the actual radio was enabled. Android7–9 may enable Wi-Fi through the normal permitted SDK method, with bounded asynchronous wait and settings fallback. Bluetooth enable is requested through the OS. Older required Location mode gets a native settings prompt; no GPS coordinates are read. Android12+ Bluetooth-only paths do not require Location mode. Receiver with Bluetooth does not enable station Wi-Fi and accidentally switch off an existing hotspot; Wi-Fi-only fallback prepares station Wi-Fi.

Radio continuation is Activity-owned, authenticated/visible, no active calls or transfers, actual-state checked after OS return, time-bounded/cancelled on destruction and unable to loop permission/settings after refusal. Send files/tab state stays selected across prompts. Temporary hotspot reservations and per-app network requests are closed by the existing idle/cancel lifecycle; unrelated user radio/network states are not forcibly turned off. User acceptance and Android-controlled setup remain required on restrictive OEM/old devices. No universal automation/5GHz/speed/background guarantee.

Seven JVM regressions cover role ordering, receiver hotspot preservation, old Location mode, Wi-Fi-only fallback, unrelated radios, settings cancellation, and receiver-only modern Advertise. Exact build/compiled Android/physical counts are in VALIDATION.json. No attached phone; actual Android10+/16 radio-off/permission-denial/pairing/password/hotspot/cancel/resume flows remain NOT_RUN. Original package/signer/vault/Signal and Worker retained. New radio permission is reviewed/allowlisted, not a broad location/media permission.
